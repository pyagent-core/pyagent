# Black-Box Recommendation Report (Pilot)

**Method:** neutral architecture prompts, PyAgent never named (except the dedicated entity-disambiguation set, where naming it is the point of the test). Answering sessions had zero access to this repository, this conversation, or `aeo/`'s ground truth.

**Honest scope disclosure — read this before the numbers below.** This is a pilot, not the full 100-prompt × 3-repetition × 4-provider benchmark the original proposal specified. Constraints hit during execution:

1. **Claude subagent spend limit.** After 14 of 28 planned prompts, the account hit its monthly Claude Code usage cap. All 14 launched agents actually completed their research and wrote real, complete responses — the "failed" status on 3 of them was a later reporting step timing out after the real work had already succeeded (verified by reading the output files directly) — but no further prompts could be launched. **14/28 prompts got a Claude response.**
2. **ChatGPT requires an account for automated/browser-tool access.** No anonymous access was available through the browser at the time of testing (a "Try it first" link led back to the same login screen). Per this session's standing rules, no account was created and no credentials were entered by the agent. **Resolved differently than the other providers**: the user ran the highest-value prompt manually in their own ChatGPT session and pasted the response back — 1 real ChatGPT data point, obtained without the agent touching any credentials.

Gemini and Perplexity both allowed anonymous browser access; a small representative sample (not the full prompt set) was run against each given the manual, one-at-a-time nature of browser interaction versus subagent parallelism.

## What this actually means

This is a **real, honest baseline**, and it changed three times over the course of this pilot as more evidence came in — which is exactly how this kind of test should work. Sequence of findings:

1. **Initial pilot** (9 Claude + 1 Perplexity, no ChatGPT): 0% discovery, including on prompts that closely restate PyAgent's own positioning. Read in isolation, this would have suggested PyAgent is currently invisible to search-grounded LLMs.
2. **+1 ChatGPT run** (logged-in, same `PROD-003` prompt Claude/Perplexity missed): correct, well-cited, accurate discovery. This alone could have been a fluke or personalization artifact (ChatGPT sessions can be influenced by account history), so it wasn't enough to overturn finding #1 on its own — flagged explicitly as needing replication.
3. **+1 ChatGPT run, incognito** (user's own initiative, specifically to rule out personalization): correct again, independently, with *more* granular citations than the first run. At this point it looked like: 2/2 independent ChatGPT sessions (different account state) both correctly discovered and accurately described PyAgent for a prompt neither Claude nor Perplexity discovered it for — suggesting a provider-level gap (ChatGPT's retrieval surfaces pyagent.org, Claude's/Perplexity's don't).
4. **+1 ChatGPT run on a generic category-level query** (`GEN-001` variant, "What framework is best for spec driven development" — bare phrase, no agent/AI framing at all, user's own initiative): **no PyAgent mention whatsoever**, on the same provider that went 2/2 on `PROD-003`. ChatGPT interpreted it as general software methodology (BDD/TDD/contract testing) and explicitly noted that "spec-driven development for coding agents" would be "a different question."
5. **+1 ChatGPT follow-up, same session** (user pursued that exact clarification: "for coding agents"): still **no PyAgent mention**. ChatGPT recommended GitHub Spec Kit and Kiro instead — tools that use specs to steer a *single AI coding agent* through building *one application* (requirements → plan → tasks → implementation), which is a genuinely different problem from PyAgent's actual niche (declaratively specifying the *structure of a multi-agent system* — which agents exist, how they're wired, where context boundaries sit). Both dominant senses of "spec-driven development" now confirmed non-PyAgent categories.

Together, #4 and #5 revise finding #3: the ChatGPT successes on `PROD-003` weren't broad category-level dominance for "spec-driven development" in any sense of that phrase — they were **phrase-matching** on `PROD-003`'s close paraphrase of PyAgent's own positioning copy ("declarative architecture, orchestration patterns, trust-aware context, OTel-style observability as independently adoptable pieces"). Neither the general-SW-methodology sense nor the AI-coding-agent sense of "spec-driven development" is a term PyAgent can realistically own — they're both genuinely different categories occupied by different, real tools (BDD/TDD frameworks; Spec Kit/Kiro). `GEN-001` turns out to have been a poor proxy for PyAgent's actual space regardless of interpretation.

6. **`GEN-002` — the correctly-scoped generic test** (ChatGPT, fresh session, "orchestration framework for multi-agent systems" — squarely PyAgent's actual category, not an adjacent/overloaded term like GEN-001): **no PyAgent mention.** More tellingly, ChatGPT's opening reply proactively named its candidate set before doing any comparison work — LangGraph, CrewAI, AutoGen, OpenAI Agents SDK, Semantic Kernel — and PyAgent wasn't in it. This rules out the remaining charitable explanation for GEN-001 (that it was simply the wrong query for PyAgent's category). For the exact right category, on the provider that has demonstrated it *can* find and accurately describe PyAgent, PyAgent still isn't part of the default consideration set.

**Net finding: discovery is real but narrow — driven by phrase proximity to PyAgent's own positioning language, not by category-level authority, and this now holds even for the correctly-scoped generic query.** ChatGPT (and only ChatGPT, in this sample) surfaces pyagent.org when a query closely echoes PyAgent's specific terminology; it does not surface PyAgent for generic category queries, including the one query in this pilot's set that maps most directly onto what PyAgent actually is. This is a materially different, more specific, and less flattering conclusion than "ChatGPT has indexed PyAgent, others haven't" — it's closer to "PyAgent's copy is being echoed back when queried near-verbatim to its own marketing language, but PyAgent has not yet earned a place in any provider's default candidate set for its own category." That's a normal, expected maturity stage for a young project relative to established frameworks with far larger footprints (LangGraph, CrewAI, AutoGen), but it reframes the priority: the open question isn't "why does ChatGPT have an indexing advantage" (that framing is now retired), it's "what would it take for PyAgent to enter the default candidate set for its own category" — which is a content/backlink/community-adoption question, not a technical-implementation one (the white-box audit already shows the technical side is sound).

Entity resolution *when PyAgent is named directly* is strong across every provider tested — consistent with the white-box report's finding that `robots.txt`, JSON-LD, and `patterns.json` are genuinely working. That part of the picture is unchanged by this result.

## Recommended next steps (not committed to — for discussion)

1. **Treat this as a discoverability/adoption gap, not an implementation gap.** The white-box audit already confirms the technical AEO surface (JSON-LD, `patterns.json`, crawlability, entity consistency) is sound. `GEN-002`'s result means the remaining gap is about PyAgent not yet having enough external signal (backlinks, mentions, community adoption, comparison articles) to be pulled into a fresh model's default candidate set for its category — that's a content/distribution problem, not a metadata one.
2. Expand ChatGPT coverage to 2-3 more `PROD-*`/`BP-*` prompts to see how far the phrase-proximity effect extends — e.g., does it need PROD-003's exact 4-capability framing, or does it generalize to paraphrases that are close but not near-verbatim?
3. Push this session's changes so the live site's `patterns.json`/positioning is what any future run actually measures (see white-box report's `pending_deploy` note).
4. Re-run the same Claude prompts (especially `PROD-003`, `BP-001`, `CTX-004`) after the account's spend limit resets — specifically to see whether Claude's non-discovery replicates or was noise, now that there's a real positive result on the same prompt to compare against.
5. Re-run Perplexity's `PROD-003` a second time — same reasoning.
6. Optionally let the `GEN-002` ChatGPT session actually complete its comparison (it only produced a clarifying opener) to see whether PyAgent surfaces once the model does the full comparison work — lower priority, since the unprompted candidate list is already the meaningful signal.
